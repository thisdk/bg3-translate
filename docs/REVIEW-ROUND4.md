## 1. 这轮是怎么做的（可复核的纪律）

- **冻结基线**：开工前记录 `HEAD`、代码 hash（`ad513e30…`）与 6 道门禁的真实输出，
  四位审计者各自复现后才动手。
- **五个角色，写范围互不重叠**：四位审计者分别负责
  `formats + pak`（归档与格式层）、`translation + types/error`（引擎与协议层）、
  `src/**`（前端）、`src-tauri + config + glossary + scripts + CI + 文档`；
  第五位是**独立验证者**，全程只读仓库（唯一允许写的是它自己的报告）：先在**冻结的 HEAD 副本**上
  做先于 writer 的对抗式发现，再在集成结果上做证伪与变异。
- **硬性质量标准**（对每个 writer 一致）：
  1. 每条结论必须附**实际执行过的命令 + 真实输出**，没跑过的一律标「未验证」；
  2. 只有在**先写出一条失败测试/探针复现**之后才允许改生产代码，修完必须给出「修复前红、修复后绿」；
  3. 不许删除或削弱任何现有测试、不许放宽门禁（`-D warnings`、`continue-on-error` 一律禁止）、
     不许新增依赖、不许在生产路径新增 `unwrap/expect/panic/#[allow]`；
  4. 新回归测试会被独立验证者做**变异实验**（把修复改回原样看是否变红），不会变红的判为无效；
  5. 「要大规模重构才划算」的项写进 backlog，不在本轮顺手做。
- **本轮学到的两条方法学教训（都已落地）**：
  1. **共享 `CARGO_TARGET_DIR` 会让验证失真**：把沙箱源码的 `CARGO_TARGET_DIR` 指向仓库
     `target/` 时，测试二进制可能链接到仓库那棵树编译出的 rlib（验证者用「沙箱源码里没有的
     字符串出现在测试二进制里」实证）。此后所有沙箱/变异实验改用隔离 target 目录并全量重建。
  2. **「当前不可达」这个论断会腐烂**：`docs/CORPUS-AUDIT.md` §D8 曾判定「忽略解析错误后用
     残缺底稿重写」不可达；本轮验证者用 App 层探针证明**可达**（底稿读失败只 `console.warn`
     就继续写回），该文档已按新证据订正。

## 2. 修了什么

### 2.1 高危（2 条）——会损坏整份产物或直接杀死进程

| # | 现象 | 后果 | 归属 |
| --- | --- | --- | --- |
| 1 | 属性之间缺空白的开始标签（如 `<LSTag a="1"b="2">`）被判成合法标签并**裸写**进产物 | 对严格 XML 解析器（独立验证用 python expat 实测）**整份文档非法** —— 丢的是这一整个本地化文件的所有译文，触发面在译文侧（模型/用户编辑） | formats F-R4-01 |
| 2 | 伪造的 `.loca` 头（`num_entries = 0xFFFFFFFF`）→ 上游库 `Vec::with_capacity(42 亿)` → **137 GB 分配失败，进程 abort** | abort 不可捕获：整个应用连同未保存的编辑一起死。`.loca` 是用户 MOD 里的文件，属不可信输入 | formats F-R4-02 |

### 2.2 中危（15 条）——静默丢数据 / 产物被判成功 / 界面卡死

| # | 现象 | 后果 | 归属 |
| --- | --- | --- | --- |
| 3 | `content_list::write` 把「目标文件存在但**读不出来**」当成「新文件」整体覆盖 | 已有译文被静默删掉，且返回 `Ok`（rename 只需目录写权限、读需文件读权限，Windows 上被占用/杀软/ACL 都会出现） | F-R4-03（红队 F-A1） |

| 5 | `.loca` 写回非原子：`File::create` 先截断，再由 writer 校验 key 长度 | 写失败把已有 `.loca` 从 160 字节变成 **0 字节** | F-R4-05 |

### 2.4 过程中自曝的一处问题（诚实记录）

审计者在实现 F-R4-01 的第一版里**自己引入了一个无界循环**（属性值引号未闭合时 `get()` 越过
末尾恒为 `None`，循环永不退出；`<LSTag a="x>` 会让公开 API 挂死），被他自己的标签探针
`timeout 900` 超时（rc=124）抓到，当场改成带边界判定的循环并补了守卫测试
（变异实验：撤掉边界 → 测试挂死）。这类「修复引入的新风险」正是本轮强调「先写探针、再改代码、
每条都做变异」的原因。

## 4. 已知取舍与未修项

这些**不是遗漏**，是明确记录、有理由的取舍。要改的话应当作为独立议题。

### 4.1 与第三轮同源、维持原裁定

| 项 | 为什么仍然不修 |
| --- | --- |
| `content_list` 写回仍丢弃注释 / DOCTYPE / 声明细节 / `<content>` 额外属性 / 元素间缩进 | 要逐字节保真得把「解析成条目再重建」改成区间原地替换，属整模块重构；本轮实测 `<!-- keep me -->` 会随写回消失，已记入 backlog |
| `raw.trim()` 会把首尾的 NBSP / 全角空格也吃掉 | 一行可改，但「文本首尾空白要不要留」是产品判断，建议与上一条一起做成区间替换时统一处理 |
| 未知实体 `&nbsp;` 二次转义 / `&amp;amp;` 每写一次剥一层 | `decode_entities` 的「还原一层」正是第三轮为修「旧版本写出的双层转义」加的防线；「合法双层转义」与「旧 bug 产物」在信息上不可分，去掉会让旧文件永久坏掉 |
| `.loca` 的 `version > 65535` 静默变 1 | 真实链路里 version 来自 u16，必然 ≤ 65535；改成报错会新增「本来能写回、现在写不回」的失败路径 |
| R-14 系列变体误合并（`deal {1} damage to {2}` 结尾句被判成系列） | 现有测试把 `Silver's Hair {1}/{2}` **必须合并**写死；收紧会让这些用例变红，按纪律不动。真实样本 41 条里 0 例，且不弄坏 XML |
| `memory` 复用仍用模糊 key（`…save?` 的译文可能补给 `…save!`） | 收紧等于改 `normalize_consistency_key`（被 memory / 系列别名 / 测试共用），会让「大小写不同视为同一专名」这条既有承诺失效 |
| `Retry-After` 未实现 | 评估结论是「能低风险实现，但**接线无法验证**」（本机无网络、无 mock 服务器，新增 mock = 新依赖，被禁）；收益仅限 429 |
| prompt 注入无边界 | 影响限于该条译文措辞，结构保真校验仍生效；改法无法验证有效性 |
| job 级 panic 只计失败、不发 `Error` 事件 | 生产路径几乎不可达（`HttpTranslator` 无 panic 点），补事件要动 IPC 事件语义 |
| `open_mod` 删旧目录与在途写回可能并发；全局单个取消令牌 | 前端 `runningRef` + 写回前的 `checked_work_root` 已挡住可达路径；本轮无新证据 |
| `extract_to_directory` 中途失败会在用户指定目录留半成品；`.lsx` 写回 `O(n·k)`（4 万字段 release 5.4s） | 清理「调用方给的目录」需要先定语义；LSX 实测规模远小于此且写回不在 UI 线程 |

| --- | --- |
| `BG3_TRANSLATE_HOME` 是相对路径时原样接受（落点 = 进程 CWD） | **不修**：这是最高优先级的用户覆盖入口；「相对路径就忽略」会偷偷改变配置落点，对正在用的人更糟。已用测试钉死行为 + 文档写明建议绝对路径 |
| `write_atomic` 覆盖只读目标：Linux 成功且丢掉只读位，Windows `rename` 会失败 | **不修，记录为已知跨平台差异**：让 Linux 也失败 = 明明能保存却被拦；让 Windows 也成功 = 要替用户清只读位。已把 Linux 行为钉住、Windows 期望写进 `cfg` 分支 |
| `Glossary::update` 允许改成已存在的 source（重复 source） | **不修**：真实官方术语表清洗后**本来就有 6 组重复 source**（组内译文相同），`matcher` 也把重复当既定行为；收紧会让这 6 组真实条目无法编辑。彻底解决要把 `update`/`delete` 改成按稳定 id 定位（动 IPC 契约）→ backlog |
| 前端 `translateAll` / `retryFailed` / `retryOne` 在 `runningRef` 守卫**之前**改 store | **未复现可达路径**（UI 三道禁用挡住）；挪进守卫会改变既有语义，建议下一轮按「入口只在守卫内改状态」重构 |
| 第二次打包的底稿是「上一次写回的结果」→ 用户点「还原」会被上次译文还原回来 | **已复现、未修**：要真正「还原成 MOD 原始文本」必须在首次写回前保存原始字节（新状态 + 新语义）；当前合并方向是「宁可保留底稿也不写英文」，比反过来安全。**建议列为下一轮议题** |
| 审计者自己发现并修掉的问题 | 见 §2.4：修复引入的无界循环，由探针超时抓到并补了守卫测试 |

## 5. 无法验证项（如实列出）

| 项 | 原因 |
| --- | --- |
| repack 后的 PAK 在**真机 BG3** 里能否加载 | 无法运行游戏；只能用产物的 XML/LOCA 语义与真实样本往返推断 |
| 真实 LLM API 的端到端行为 | 没有 key，也刻意不发外部请求；错误载荷、`finish_reason`、各网关 SSE 形态都用注入字节验证 |
| Windows 专属语义：大小写不敏感文件系统上的**物理覆盖**、`rename` 覆盖已存在文件、保留设备名/ACL | 本机是 Linux；相关修复依赖跨平台语义（`ErrorKind::NotFound`、`fs::rename`），Windows 分支只能由 CI 覆盖 |
| `release.yml` 的 4 段 PowerShell 与 GitHub Actions 的真实运行 | 本机没有 `pwsh`，不能跑 Actions；静态审查未发现新缺陷，CI 步骤的 `run:` 原文已在本地真实执行 |
| 真实 Tauri 运行时的并发命令与窗口事件（`win.minimize()` 是否真的 reject） | 不跑真后端；用注入 reject 的 mock 复现与验证 |
| 真实游戏 `.loca` 语料 | 仓库里没有任何真实 `.loca`（样本 MOD 只有 contentList XML）；**因此布局自检采取保守策略**：只挡「上游 `read_exact` 物理上不可能成功」的布局，并用 5 条正向用例兜住误判 |
| BG3 真实的中文本地化目录名（`Chinese` vs `ChineseSimplified`） | 无真机、本机无法联网检索；本轮只保证「我们自己的产物在下一轮能被认出来」这一内部一致性（`TARGET_LANGUAGE = "Chinese"` 是既有的产品决策） |
| 上游恶意 `.loca` 的 GB 级分配 | 无法安全触发；用验证者实测的两次 SIGABRT 作为「修复前确实会 abort」的证据 |
